## 一、项目定位

本会话专门负责继续推进：

**LanternBox / 壳中灯 FT-02 自研随身终端的硬件设计、能力验证、固件联调、供电规划、PCB 前置设计与整机集成。**

FT-02 是 LanternBox 系统中的第二代自研便携终端，目标是实现一台：

- 完全离线运行
- 低功耗、可长期待机
- 墨水屏显示
- 实体按键操作
- 支持本地存储
- 支持 GNSS 定位
- 支持 LoRa 离线通信
- 支持录音与音频播放
- 支持 USB-C 供电、调试与物理同步
- 后续可扩展传感器、摄像头和外接键盘

的模块化随身终端。

FT-02 不是普通 ESP32 开发板演示项目，而是未来需要完成：

- 正式原理图
- 自研 PCB
- 电源系统
- 外壳设计
- 模块固定
- 接口布局
- 长期运行验证

的整机研发项目。

## 四、当前主控与系统限制

### 主控

当前原型主控：

```text
ESP32-S3 DevKit N16R8
```

新增模块前必须同时检查：

- GPIO 是否在实际开发板上引出
- 是否属于启动配置引脚
- 是否影响原生 USB
- 是否影响烧录与串口调试
- 是否支持目标外设功能
- 是否允许深度睡眠唤醒
- 是否与现有 SPI、I2C、UART 或 I2S 冲突

不能只判断“能运行”，还要考虑 PCB 化和长期稳定性。

### 原生 USB 锁定

| 功能 | GPIO | 规则 |
|---|---:|---|
| USB D- | GPIO19 | 禁止作为普通外设使用 |
| USB D+ | GPIO20 | 禁止作为普通外设使用 |

GPIO19、GPIO20 必须保留给 ESP32-S3 原生 USB。

### 5.2 CardKB2 输入

设备：

```text
M5Stack Unit CardKB2
```

通信：

```text
I2C
地址：0x5F
```

实际接线：

| CardKB2 标注 | ESP32-S3 |
|---|---:|
| G26 / SDA | GPIO47 |
| G25 / SCL | GPIO21 |
| VCC | 3.3V |
| GND | GND |

代码基线：

```cpp
Wire.begin(47, 21);
```

固定规则：

```text
SDA = GPIO47
SCL = GPIO21
CardKB2 地址 = 0x5F
I2C 频率 = 100 kHz
```

不要改回 SDA=GPIO4、SCL=GPIO5，也不要默认重新扫描其他引脚。

已验证：

- GPIO47 / GPIO21 新接线已完成实机验证
- I2C 初始化成功
- 设备 0x5F 可稳定识别
- 按键读取成功
- 首页卡片切换成功
- 确认、帮助、返回等输入可用

当前临时映射：

| CardKB2 按键 | FT-02 输入 |
|---|---|
| D / d | 上 |
| Z / z | 左 |
| X / x | 下 |
| C / c | 右 |
| Enter / Space | 确认 |
| H / h | 帮助 |
| Esc / Backspace / B / b | 返回 |

CardKB2 当前用于输入能力验证，不代表最终整机一定采用完整 CardKB2。

### 5.3 microSD / TF 存储

设备：

```text
Waveshare Micro SD Storage Board
```

当前正式路线：

```text
SPI 模式
独立 SPIClass(FSPI)
SPI Mode3
```

接线：

| SD 模块信号 | ESP32-S3 GPIO | SPI 含义 | 状态 |
|---|---:|---|---|
| CD | GPIO7 | 插卡检测 | 已验证 / 锁定 |
| D3 | GPIO6 | CS | 已验证 / 锁定 |
| CLK | GPIO15 | SCK | 已验证 / 锁定 |
| CMD | GPIO16 | MOSI | 已验证 / 锁定 |
| D0 | GPIO17 | MISO | 已验证 / 锁定 |
| D1 | 不接 | - | SPI 模式不使用 |
| D2 | 不接 | - | SPI 模式不使用 |
| 3.3V | 3V3_EXT | 外设电源 | 已验证 |
| GND | GND | 共地 | 已验证 |

最终接线基线：

```text
SD 3.3V -> 3V3_EXT
SD GND  -> GND
SD CD   -> GPIO7
SD D3   -> GPIO6
SD CLK  -> GPIO15
SD CMD  -> GPIO16
SD D0   -> GPIO17
SD D1   -> NC
SD D2   -> NC
```

已验证结果：

```text
Status: SD INFO OK
CD:0 Cap:29823MB
Sig:55 AA
```

结论：

- GPIO7 的 CD 插卡检测有效
- 当前板子 CD=0 表示已插卡
- 32GB SD 卡容量读取约 29823MB，属于正常换算
- block0 读取成功
- 55 AA 签名正常

固定协议基线：

```text
独立 SPIClass(FSPI)
SPI Mode3
当前不使用 SD_MMC
当前不使用 SD.begin()
```

已废弃或暂不采用的路线：

| 路线 | 结果 | 结论 |
|---|---|---|
| SDMMC 1-bit | 失败 | 不作为当前主线 |
| SDMMC 4-bit | SDMMC_MOUNT_FAILED | 不作为当前主线 |
| 全局 SPI 对象 | 曾卡在 PROBING | 不作为当前主线 |
| bitbang SPI Mode3 | 成功 | 保留为诊断底座 |
| 独立 SPIClass(FSPI) Mode3 | 成功 | 当前正式主线 |

GPIO14 已从 SD CS 释放，不再作为 SD CS。

## 七、当前供电基线

当前原型供电原则：

```text
ESP32-S3 DevKit -> USB-C 供电
外设 3.3V       -> 外部 3.3V DC-DC 稳压模块
所有 GND        -> 共地
```

重要规则：

```text
ESP32-S3 通过 USB 供电时，不要把外部 3.3V 直接反灌到开发板 3V3 引脚。
外部 3.3V 只作为外设供电总线。
所有模块必须共地。
```

建议电容：

```text
3V3_EXT 总线：100uF ~ 470uF
SD 模块附近：100nF + 10uF 或 47uF
```

以后增加任何模块时，都要同步记录：

- 工作电压
- 峰值电流
- 平均功耗
- 待机功耗
- 是否需要独立稳压
- 是否需要负载开关或 MOSFET 控制
- 是否会干扰 GNSS、LoRa 或音频

## 十一、下一步任务

当前最合理的下一步不是立刻接 GNSS 或 LoRa，而是先把已经验证的 SD 底层通信推进到可用存储能力。

建议顺序：

### 第一阶段：SD 文件系统

1. 保持现有接线不变
2. 保持独立 SPIClass(FSPI)
3. 保持 SPI Mode3
4. 验证 FAT32 引导扇区与分区信息
5. 验证根目录读取
6. 验证文件读取
7. 验证新建、写入、关闭和重新读取文件
8. 验证断电后文件完整性
9. 验证剩余空间统计
10. 验证插拔和异常卡处理

### 第二阶段：SD 状态接入 UI

将真实状态接入顶部状态栏：

- 未插卡
- 已插卡但未识别
- 文件系统可用
- 文件系统故障
- 只读或写入失败

不要只显示一个固定图标。

### 第三阶段：日志落盘

在文件系统稳定后再实现：

- 系统日志
- 用户操作记录
- GNSS 轨迹
- 录音索引
- Core 同步清单
